# Codex Quota Widget 产品需求文档

版本：0.1｜日期：2026-11-05｜状态：原型已确认，Tauri MVP 已实现，验证范围见 VERIFICATION.md。

## 1. 产品目标与范围

为 macOS 上的 Codex 用户提供常驻桌面的轻量额度卡片：查看当前账号、5 小时与周额度、恢复时间和重置卡；需要时选择一张重置卡使用。

首版面向当前登录的 ChatGPT 账号，不做账号池、账号切换、代理、模型管理、聊天和消费统计。交付形态为本地 macOS 小应用；Codex 插件接入属于后续可选项。

## 2. 已确认的视觉与交互

视觉以 [第四版原型](../prototype/card-prototype-v4.png) 为准。第一版中的刷新设置和用卡确认作为交互参考，视觉统一到第四版。

- 磨砂半透明玻璃卡片、细描边、克制的冷青色点缀。
- 两个分段光环仪表盘，中央显示剩余百分比，额度终点有微亮光点。
- 展开态显示账号、套餐、额度、恢复倒计时、重置卡和刷新状态。
- 点击右上角减号收起；精简态为迷你横条：一行账号与套餐，两行细额度条显示 5 小时/周剩余百分比与恢复时间，仅隐藏重置卡列表。
- 点击加号恢复展开态。记住上次状态；首次默认精简态为设计默认值。
- 重置卡按到期时间升序排列，未知到期时间排在后面；每张卡独立提供使用入口。
- 不自动用卡、不为每次刷新播放持续动画。

原型中的蓝色壁纸是展示背景，不是应用窗口的一部分。实际卡片透出用户桌面背景；不得把整张原型当作界面贴图。原型中的账号、额度和卡片均为演示数据。

## 3. 用户故事

| 编号 | 用户故事 | 结果 |
|---|---|---|
| US-01 | 我打开 Codex，希望立即看到剩余额度 | 后台助手已启动时自动显示卡片 |
| US-02 | 我想确认现在用的是哪个账号 | 展开或精简态均可查看与桌面端一致的账号及套餐 |
| US-03 | 我只想快速看额度，不想占太多桌面空间 | 一键收起为迷你额度条 |
| US-04 | 我想知道额度何时恢复 | 每个仪表盘下显示恢复倒计时 |
| US-05 | 我想控制刷新频率 | 设置预设或自定义间隔，并能手动刷新 |
| US-06 | 我担心重置卡过期浪费 | 展开查看每张卡的绝对到期时间和剩余时间 |
| US-07 | 我想使用指定卡片 | 在该卡片上点击使用、确认后提交指定卡片 |
| US-08 | 网络断开时我仍想知道上次额度 | 显示带时间标识的旧数据，不冒充实时状态 |

## 4. MVP 功能列表

| 编号 | 功能 | 规则 |
|---|---|---|
| F-01 | 启动联动 | 用户开启登录启动后，助手在后台监听 Codex；已运行的 Codex 同样能识别 |
| F-02 | 窗口管理 | 可拖动、记忆位置和展开尺寸、可选置顶；通过菜单栏显示、隐藏和退出；菜单栏图标可在设置中隐藏，隐藏后仍可从展开卡片进入设置恢复 |
| F-03 | 当前账号 | 自动识别当前 Codex 账号；切换后更新，识别不一致时不得继续提供用卡入口 |
| F-04 | 额度仪表盘 | 显示剩余比例，不把它换算成剩余消息数或 token 数；缺失窗口显示“未提供” |
| F-05 | 恢复倒计时 | 根据服务端时间计算；倒计时到零触发刷新，不在本地直接改成 100% |
| F-06 | 自动刷新 | 默认 5 分钟；预设 1/5/15 分钟，自定义整数 1–60 分钟；可关闭自动刷新 |
| F-07 | 手动刷新 | 展开态按钮及菜单栏入口；刷新期间合并重复刷新请求 |
| F-08 | 重置卡列表 | 显示数量、状态、到期时间和倒计时；优先使用服务端标题，没有标题时给简短本地序号 |
| F-09 | 指定用卡 | 显示账号、所选卡及到期信息；确认后使用，不自动改为另一张卡 |
| F-10 | 状态反馈 | 登录失效、接口不可用、无卡、详情未提供、数据陈旧等状态可区分 |
| F-11 | 设置持久化 | 保存刷新间隔、置顶、展开状态、展开尺寸、位置和启动联动偏好 |

首次使用必须说明：只有后台助手正在运行，才能监听 Codex 启动。关闭整个助手后不会凭空自动唤醒；系统未允许登录启动时展示实际状态。Codex 退出后默认隐藏卡片并暂停轮询，助手保留监听；休眠期间不轮询，唤醒后按是否运行 Codex 决定刷新。

## 5. 数据与操作规则

### 5.1 额度

- 优先读取 Codex 主额度桶，依据窗口实际时长匹配 5 小时和周额度；不盲目把所有 primary/secondary 字段固定命名。
- `剩余比例 = 100 − 已用比例`；仪表盘按有效原始比例绘制，显示整数百分比。
- 服务端未提供、账号不支持、网络读取失败分别呈现；不能补造 0% 或 100%。
- 多额度桶的选择规则须在开发前验证；首版不扩展为所有模型额度面板。

### 5.2 重置卡

- 卡片绝对到期时间按系统时区展示，倒计时在本地更新，不随每次倒计时变化发送请求。
- 无到期时间显示“未提供到期时间”，不得猜测有效期。
- 可用数量以服务端汇总为准；详情未提供和空列表是不同状态。详情不全时提示“当前显示部分卡片”。
- 过期或已使用卡片不可提交；服务端最终决定是否可用和实际重置范围。
- 点击具体卡片必须提交该卡片身份。接口版本不支持指定卡片时明确提示，不静默降级为“自动选择最近到期卡”。
- 使用成功后重新读取额度与卡片。无可重置额度、无可用卡、结果待确认分别反馈，不统一显示“成功”。
- 请求结果不明时先查询状态，不自动再消耗一张卡。

## 6. 非功能需求

| 类别 | 要求与验证方式 |
|---|---|
| 可读性 | 在浅色、深色和复杂壁纸下检查读数；支持系统降低透明度设置 |
| 可访问性 | 按钮有文本辅助标签；键盘可操作；颜色之外保留数字、状态文字 |
| 性能 | 无持续背景动画；倒计时按分钟显示、可见时每 30 秒检查；隐藏或休眠时停用界面定时器 |
| 性能目标 | 卡片展开/收起目标小于 200ms；空闲主应用 CPU 平均低于 1%，内存目标低于 150MB；指定测试机实测，另报 App Server 和完整进程树开销 |
| 网络 | 不通过模型推理查询额度；刷新遵守设置；限流时依据服务端建议延后 |
| 数据安全 | 不存储或输出 token、密码、认证文件内容；数据仅保存在本机 |
| 可靠性 | 显示最近成功刷新时间；失败不覆盖有效缓存；缓存不能作为允许用卡的唯一依据 |
| 兼容性 | 暂定 macOS 13+、Apple Silicon 优先；实际最低版本和 Codex 版本在技术预研后锁定 |
| 发布 | 首次个人本机使用；正式分发前补签名、公证与安装验证 |

上述性能数值是目标，尚未测量，不是交付事实。

## 7. 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC-01 | 助手已运行，打开 Codex | 2 秒内出现卡片；网络数据可随后加载；不抢输入焦点 |
| AC-02 | 助手启动时 Codex 已运行 | 识别并显示一次，不产生重复窗口 |
| AC-03 | 切换展开/精简 | 精简态无重置卡列表、保留账号与套餐；恢复后内容完整；重启保留状态 |
| AC-04 | 输入已知额度测试样本 | 数字和亮起刻度对应；缺失值不伪装成有效额度 |
| AC-05 | 设置 1/5/15 分钟和自定义值 | 配置持久化；后续调度使用新间隔；倒计时不增加网络请求 |
| AC-06 | Codex 切换账号 | 下一次账户同步后只显示新账号数据；用卡前再次确认所属账号 |
| AC-07 | 两张卡不同到期时间 | 排序、日期、倒计时一致；未知日期有明确文字 |
| AC-08 | 指定卡 B，卡 A 更早到期 | 模拟测试证明请求指向 B；本次开发不真实消费，由用户自行使用 |
| AC-09 | 无详情、无卡、接口失败 | 三种界面状态可区分；汇总数量不被空详情错误清零 |
| AC-10 | 用卡请求成功或结果异常 | 按实际结果反馈；成功后重新读取；结果不明不自动发起新消耗 |
| AC-11 | 离线、登录失效、休眠恢复 | 旧数据标记清楚；不会自动换账号或循环高频请求 |
| AC-12 | 玻璃材质与桌面行为 | 对照第四版；背景来自桌面；拖动、置顶、键盘与多屏基本行为通过手工检查 |

## 8. 已知证据与待验证项

2026-11-05 查阅的 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server#8-earned-rate-limit-resets-chatgpt)明确描述指定卡片消费能力。官方能力存在不代表本机已验证通过。

待验证：本机接口版本、与 Codex 桌面端的账号一致性、具体账户的重置卡字段及实际重置范围。用户报告参考项目优先使用最近到期卡；本项目不把该行为视为指定卡片能力的替代品。

## 9. 后续迭代候选

- 到期提醒、低额度提醒，默认不开启。
- 显示透明度调节、深浅主题和更窄的布局。
- 多显示器体验优化。
- 手动安装的 Codex 插件入口，用于显示卡片或触发刷新。

以上不混入首版必做项。
